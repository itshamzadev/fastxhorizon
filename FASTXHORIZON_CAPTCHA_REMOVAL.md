# Fast X Horizon CAPTCHA Removal

## Scope

The active Fast X Horizon default theme no longer displays or requires CAPTCHA
in customer, seller, admin, contact, or SMS-test flows. Technical compatibility
routes, the dormant service, translation keys, and third-party libraries were
kept unless they were part of an active flow.

## Systems found

- Default image CAPTCHA generated by Gregwar Captcha.
- Google reCAPTCHA v3 integration through RecaptchaService.
- Firebase phone-auth reCAPTCHA containers in the web templates.
- Shared CAPTCHA/session routes and legacy JavaScript helpers.
- Admin reCAPTCHA configuration page.
- Captcha-capable third-party Firebase/Google libraries.

The local business_settings recaptcha setting was already disabled and was
verified as:

{"status":0,"site_key":"","secret_key":""}

## Active flows changed

Removed rendered CAPTCHA markup and active validation from:

- Customer login, OTP login, registration, account verification, OTP resend,
  forgot password, and password recovery.
- Seller login, registration, forgot password, OTP verification, and reset
  password pages.
- Admin login.
- Public contact form and its contact provider.
- Admin SMS test form.

The seller registration flow still validates business identity, legal documents,
phone, email, password, and all existing fields. Only CAPTCHA-specific
validation was removed.

## Backend changes

Removed active RecaptchaService verificationStatus calls from the customer,
seller, admin-login, contact, and SMS-test request paths. CAPTCHA traits were
also removed from the active registration/login request classes where they were
unused.

The reCAPTCHA admin route remains as a compatibility route, but its page now
redirects to the admin dashboard and any update is forced to status 0. The
database setting/column was not removed.

## Settings and dormant references

The reCAPTCHA link was removed from the normal admin navigation. The following
remain intentionally dormant for compatibility or package support:

- app/Services/RecaptchaService.php
- app/Traits/RecaptchaTrait.php
- legacy CAPTCHA/session routes
- legacy translation keys
- Firebase/Google vendor libraries
- unused legacy CAPTCHA partials and helper functions
- inactive theme_aster templates

No active default-theme template includes those CAPTCHA partials.

## Mobile and API impact

The User and Vendor Flutter source trees contain no CAPTCHA/reCAPTCHA
references. No CAPTCHA validation reference was found in the REST API
controllers. Firebase/package IDs and API field names were not changed.

## Security preserved

The change does not remove CSRF protection, guest/auth middleware, password
validation, phone/email validation, account verification, OTP resend/attempt
controls, login failure handling, API middleware, or authorization checks.

## Validation

Passed:

- PHP lint for all changed PHP controllers, requests, and provider.
- php artisan optimize:clear.
- php artisan view:cache.
- HTTP 200 with no CAPTCHA markup on homepage, admin login, customer login and
  registration, customer recovery, seller login and registration, seller
  recovery, and /contacts.
- Invalid admin/customer/seller auth and recovery submissions returned normal
  validation/auth responses without CAPTCHA errors.
- Contact submission validation returned normal field validation without CAPTCHA
  errors.

php artisan route:list remains blocked by the existing placeholder Firebase
server-key configuration (Put your firebase server key here.); this is
unrelated to CAPTCHA removal. The HTTP route checks and Blade cache completed
successfully.

## Final status

Active CAPTCHA visible or required in Fast X Horizon customer, seller, or admin
workflows: **NO**.
